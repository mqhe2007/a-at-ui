# Security Model

A@UI's security design is based on **declarative component constraints** — an Agent can only use pre-registered components and cannot inject arbitrary code or manipulate unauthorized DOM.

## Component Whitelist

Every UI component that an Agent can drive must be declared in `a-at-ui.manifest.json`. The Runtime builds a component map at initialization:

- Plugin install phase: iterates over every component name in the manifest, resolving each from the explicit component map or Vue global registry
- Component not found → initialization error, refuses to start
- Receiving a component name not declared in the manifest → dispatch error

An Agent cannot send a `render` command for a component that isn't registered.

## Command Validation

Every command is structurally validated before dispatch:

**render**
- `type` must be `"render"`
- `component` must be a string
- Must not include `widgetId`

**update**
- `type` must be `"update"`
- `widgetId` must be a non-empty string
- `params` must be an object

**destroy**
- `type` must be `"destroy"`
- `widgetId` must be a non-empty string
- Must not include `component` or `params`

Invalid commands encountered in the stream are never silently swallowed — the raw payload and error are exposed through the `onError` channel.

## widgetId Isolation

`widgetId` is generated by the frontend Runtime on `render` (`crypto.randomUUID()`). The backend Agent cannot specify or predict the widgetId. widgetId references in update and destroy commands are checked by the Runtime; references to non-existent widgets trigger a warning and are skipped.

## Payload Serialization Check

Component event payloads undergo `isSerializableValue()` validation before being emitted to the Agent layer, ensuring only JSON-compatible types (string, number, boolean, null, arrays, plain objects). Payloads containing functions, DOM elements, or other runtime objects are rejected.

## Lifecycle Declarations

Components explicitly declare `lifecycle.render`, `lifecycle.update`, and `lifecycle.destroy` in the manifest. The Runtime checks these declarations before executing an operation:

- Lifecycle operation declared as `false` → error thrown
- Unrecognized command type → "Unsupported command type" error

## Error Channel

All invalid commands, parse failures, and dispatch errors are uniformly exposed through the `onError` callback — they are never discarded internally. See [Error Reference](./errors) for a detailed list.
